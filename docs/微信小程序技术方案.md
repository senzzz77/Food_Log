# 饮食计划 · 微信小程序改造技术方案

> 版本：v0.1（方案稿）
> 目标：在现有 Web 应用（React + Fastify + MySQL）基础上，新增微信小程序端，复用后端 API 与核心业务逻辑，落地「登录 → 拍照识别食物 → 设置克重 → 记录一餐」的最小闭环。

---

## 1. 目标与范围

### 1.1 目标

- 新增微信小程序端，用户可随时随地拍照记录饮食。
- 复用现有后端 API、数据库、AI 食物识别能力（千问 `qwen3.5-plus`）。
- 先跑通 MVP 闭环，再逐步对齐 Web 端的完整功能。

### 1.2 不在本期范围

- 食谱浏览、饮食计划（planner）、身体档案编辑器、趋势图表等 Web 端完整功能，MVP 阶段不搬。
- 小程序内的社交/分享/消息推送。

## 3. 小程序技术选型

- **框架：Taro 4.x（React 语法）** —— 与现有 React 技术栈一致，复用 Zustand、TypeScript、业务逻辑。
- **UI 组件库：NutUI-React-Taro**（京东，配套 Taro）或按需手写轻量组件。
- **状态管理：Zustand 5**（与 Web 端一致）。
- **请求：`Taro.request` / `Taro.uploadFile`**，封装成与现有 `api-client.ts` 同接口的适配器。
- **登录态：`Taro.setStorageSync`** 持久化 `token`，请求拦截器自动附带 `Authorization`。

> 备选：uni-app（Vue 语法，与本项目 React 栈不匹配，不推荐）。

### 4.1 共享层策略（MVP 采用轻量方式）

- **数据契约**：以 `src/types/domain.ts` 为唯一来源，小程序端通过软链或复制保持同步。
- **纯函数**：`calculations.ts`、`constants.ts` 复制/软链到 `miniapp/src/lib`。
- **不引入 monorepo**：MVP 阶段避免改造现有 Web 工程，最快落地。后续若两端共享逻辑增多，再抽 `packages/shared`。

### 4.2 后端改造（见第 5 节）

核心后端可复用，仅需新增一个图片上传接口、补全生产环境变量。

## 5. 后端改造清单

### 5.1 新增图片上传接口（关键）

**问题**：现有 [`POST /api/vision/recognize`](file:///d:/Code/%E9%A5%AE%E9%A3%9F%E8%AE%A1%E5%88%92/server/src/routes/vision.ts) 接收 JSON 里的 `imageBase64`。小程序拍照图片较大，转 base64 后易超 `Taro.request` 请求体限制，且 JSON 传输低效。

**方案**：新增 `POST /api/vision/recognize-upload`，接收 `multipart/form-data`（字段名 `file`），复用现有识别逻辑，返回相同的 `{ items }`。

**改动**：

1. 新增依赖 `@fastify/multipart`。
2. 在 `index.ts` 注册插件。
3. 抽出公共识别函数，供两个接口复用：

```ts
// server/src/vision.ts —— 抽出“识别 + 映射食物库”为公共函数
export async function recognizeAndMap(buffer: Buffer, mimeType: string) {
  const imageBase64 = buffer.toString("base64");
  const foods = await recognizeFoodsFromImage(imageBase64, mimeType);
  const [rows] = await database.query<FoodRow[]>(/* 全量食物库 */);
  return foods.map((item) => {
    const matched =
      rows.find((row) => row.name === item.name) ??
      rows.find(
        (row) => row.name.includes(item.name) || item.name.includes(row.name),
      );
    return {
      name: item.name,
      food: matched ? toFood(matched) : null,
      estimate: item.estimate,
    };
  });
}
```

4. 新路由：

```ts
// server/src/routes/vision.ts
app.post(
  "/recognize-upload",
  { onRequest: [app.authenticate] },
  async (request, reply) => {
    const file = await request.file();
    if (!file) return reply.code(400).send({ message: "缺少图片文件。" });
    const mimeType = file.mimetype;
    if (!/^image\/(jpeg|png|webp)$/i.test(mimeType))
      return reply.code(400).send({ message: "仅支持 jpeg/png/webp 图片。" });
    const buffer = await file.toBuffer();
    if (buffer.length > 8 * 1024 * 1024)
      return reply.code(400).send({ message: "图片过大。" });
    const items = await recognizeAndMap(buffer, mimeType);
    return reply.send({ items });
  },
);
```

> 前端小程序端用 `Taro.uploadFile({ url: '/api/vision/recognize-upload', filePath })`，附带 `Authorization` header。

### 5.2 生产部署变量补全（当前缺陷）

[`docker-compose.production.yml`](file:///d:/Code/%E9%A5%AE%E9%A3%9F%E8%AE%A1%E5%88%92/docker-compose.production.yml) 的 `api` 服务 `environment` 缺少 `DASHSCOPE_*`，会导致上线后 AI 识别失效。需补充：

```yaml
DASHSCOPE_API_KEY: ${DASHSCOPE_API_KEY}
DASHSCOPE_MODEL: ${DASHSCOPE_MODEL:-qwen3.5-plus}
DASHSCOPE_BASE_URL: ${DASHSCOPE_BASE_URL:-https://dashscope.aliyuncs.com/compatible-mode/v1}
```

## 6. 小程序 MVP 功能闭环

### 6.1 页面与路由

| 页面               | 路径                  | 复用 API                                                            |
| ------------------ | --------------------- | ------------------------------------------------------------------- |
| 登录/注册          | `pages/login`         | `POST /auth/login`、`POST /auth/register`                           |
| 档案选择           | `pages/profiles`      | `GET /profiles`                                                     |
| 饮食记录（首页）   | `pages/diary`         | `GET /diaries/:profileId`、`DELETE /entries/:id`                    |
| 拍照结果（含克重） | `pages/camera-result` | `POST /vision/recognize-upload`、`POST /diaries/:profileId/entries` |

### 6.2 核心流程

1. 登录 → 存 `token` → 选/建档案。
2. 点击「拍照」→ `Taro.chooseMedia` 选图。
3. `Taro.uploadFile` 上传 → 得到 `items`。
4. 展示识别结果：命中食物库用库数据；未命中显示 AI 估算（只读 + 编辑按钮，与 Web 端一致）。
5. 用户填写克重 → 逐条或批量 `POST /diaries/:profileId/entries`（`source: "photo"`）。
6. 刷新当日日记与热量汇总。

### 6.3 关键实现点

- **图片压缩**：上传前用 canvas 将图片压缩到 ≤ 2MB（宽高等比缩放、质量 0.8），避免 `uploadFile` 超限。
- **登录态拦截**：统一封装 `request`，401 时跳登录页。
- **AI 估算可编辑**：沿用 Web 端已实现的「只读展示 + 编辑按钮」交互。
- **热量计算**：复用 `lib/calculations.ts` 中「每 100g 数值 × 克重 / 100」的逻辑。

## 7. 部署与上线清单

### 7.1 小程序侧

1. 注册微信小程序账号，完成主体认证。
2. 域名备案（小程序 `request`/`uploadFile` 合法域名要求 HTTPS + 大陆备案）。
3. 在「开发管理 → 服务器域名」配置 `request` 与 `uploadFile` 合法域名。
4. 小程序后台配置 `appid`，Taro 工程接入微信开发者工具调试。
5. 上传代码、提交审核、发布。

### 7.2 后端侧

1. 准备服务器 + 已备案域名，解析 A 记录。
2. 补全第 5.2 节的 `DASHSCOPE_*` 变量。
3. 根目录建 `.env`，填 `MYSQL_*`、`JWT_SECRET`、`APP_DOMAIN`、`DASHSCOPE_API_KEY`。
4. 构建并启动：

```bash
docker compose -f docker-compose.production.yml up -d --build
```

5. Caddy 自动签发 HTTPS；验证 `https://域名/api/health` 返回 `{ "status": "ok" }`。

## 9. 风险与待确认项

1. **小程序主体与备案**：个人/企业主体影响能否开通 `request` 合法域名与类目资质（饮食类通常不需要特殊资质，但需备案）。
2. **图片上传体积上限**：需实测 `Taro.uploadFile` + Fastify `bodyLimit`（当前 10MB）在真机上的表现，确定压缩阈值。
3. **AI 调用成本**：`qwen3.5-plus` 已关闭思考模式（`enable_thinking: false`），但每次识别仍产生 token 费用，建议加服务端限流/用量提示。
4. **共享层演进**：MVP 用复制/软链，若后续两端逻辑膨胀，再评估抽 `packages/shared` 的 monorepo。
